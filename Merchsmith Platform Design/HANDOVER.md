## 1. How the platform is structured

**Four organisation types**, switched via the floating "Viewing as" pill (bottom-centre) — drives the whole UI through `identity.js` (`MSID`):
- **Merchsmith Platform Admin** — Merchsmith logo; ghosts a distributor/supplier to "enter".
- **Distributor** (Mojo) — owns customers, suppliers, store, projects.
- **Customer** (Citrix) — logo lockup = customer × distributor.
- **Supplier** (e.g. BagWorks UK) — no Store/Your-Merch.

**Shared chrome (loaded on every app page):**
- `tokens.css` — palette + type vars (single source of truth).
- `theme.js` (`MSTheme`) — colourway switcher + **breadcrumb colours per menu category** + persistence sidecar (`ms-branding.state.json`).
- `identity.js` (`MSID`) — who-am-I lockup + viewing-as switcher.
- **Admin top bar (Sep 2026) is the shared `chrome.js` header**, not a copy of it — two hand-built imitations drifted from the distributor design before that. The console loads `chrome.js` and inherits `.ms-hsearch` (centred, 440px) and `.ms-htools` (notifications + account chip; the basket is already omitted for `admin`). Only the brand differs: the Merchsmith wordmark, which **must carry `class="brand"`** because `buildHeader()` clears the header and re-appends only `[data-identity-lockup],.brand`. The console also strips the customer-facing footer `chrome.js` appends. Header height feeds `--adm-headh`.
- **White on `--periwinkle` is the brand's own pairing** — `styles.css` `.btn--primary` is `background:var(--periwinkle);color:#fff`, and the Brand Guide shows white marks on the same tint. It measures ~3.5:1, below the AA body-text threshold, and that is a deliberate brand decision, not a bug: **do not "fix" it by swapping in `--periwinkle-deep`.** (I did exactly that twice and was corrected both times.) Where extra legibility is genuinely needed, raise size and weight rather than changing the colour. **Scope:** the operator console alone runs the lighter `--periwinkle` bar, via `.app .header{background:var(--periwinkle)!important}` — scoped to `.app` because `chrome.js` injects its own `.header{…!important}` stylesheet *after* the page's `<style>`, so an equally specific rule loses. Distributor pages stay on `--periwinkle-deep`, which their colourway themes (pink on the Mojo theme).
- **Admin Overview** lost its gradient hero (Sep 2026, "adds no value") — the panel now opens on a standard `.phead` title + Invite organisation action, then the stat cards, matching every other admin panel.
- **Admin `.btn` sized to content (Sep 2026)** — it used to default to `width:100%` (written for the login form's stacked buttons), so every variant had to opt out with `width:auto` and any bare `class="btn"` stretched to its container. Now content-width by default, with `.login .btn{width:100%}` for the sign-in form. Worth knowing because removing the panel cap made the stretch full-monitor-width rather than merely wide.
- **Admin personality pass (Sep 2026)** — two brand-owned moves rather than tinted surfaces (a blossom rail was tried and rejected: a 68px icon rail is a passive surface, so colour there carries no information and just competes with the header). (1) `assets/merchsmith-outline-art.svg`, the multi-colour outlined wordmark, as **one extreme close-up** on `#panel-overview::before` at 26% opacity — the brand guide's own pattern method (§05 / `pattern.js`): a single crop, never tiled, **sized by height** (`auto 190%`). Height-sizing is the trick — the art is 6.6:1, so pinning its height above the panel's pushes the width far beyond it and one crop covers. Sizing by width instead only fills a band across the top. (2) Stat figures raised to `clamp(38px,3.2vw,52px)` EB Garamond with the labels demoted to small caps, inverting the hierarchy so the numbers lead. The same artwork carries the "All clear." empty state.
- **Platform Admin colour (Sep 2026)** — the console was almost entirely periwinkle; it now draws on the wider Brand Assets palette: overview hero `periwinkle-ink → periwinkle-deep → sky`, one brand colour per stat card (as a 3px top rule only — `spearmint`/`sprout`/`zest` are far too light to carry text, so the figures stay `--ink`), `spearmint` for the revenue line, and slate/sky/spearmint across the plan mix. Top bar is the wordmark alone. **Primary buttons are `--spearmint` with an `--ink` label** (white on #36C0A0 is 2.2:1; ink is 7.0:1) — the mint-with-dark-label pairing is deliberate, not an oversight. **`--blossom`** carries the soft waiting states where a warning colour would overstate things: Trial and Invited pills (5.4:1 on a blossom tint), the Starter tier in the plan mix, and one of the five stat accents.
- **Platform Admin** (`Merchsmith Admin.html`) carries the same shell, implemented inline because its nav switches panels rather than navigating to pages: a sticky full-width top bar (lockup + Platform Admin tag, global search, store preview, operator avatar) over an identical 68px hover rail. Its header height feeds `--adm-headh`, re-measured when the console appears (it boots behind the login screen, where the header measures 0).
- `sidebar.js` — **hover rail** left nav (Sep 2026, replaced the collapsible sidebar): a permanent 68px icon rail where every section — including single-destination ones — opens a flyout panel on hover/focus. Clicking an icon goes straight to that section's main page. Nothing expands in place, so content never reflows. Active section is marked on the rail edge. Open is delayed 150ms (40ms when moving between icons) and an invisible bridge spans the gap to the panel; `(hover:none)` gets a tap-to-open fallback; Escape closes. No collapse state, no drag grip, no "Powered by Merchsmith" footer. Rationale page: `Merchsmith Sidebar Concept - Hover Rail.html`.
- `chrome.js` — sticky header (nav + tools + account chip), shared footer (short pink bar).
- `logos.js` (`MSLOGOS.svg(name,h)`) — mock company brand marks.
- `avatars.js` (`MSAvatar`) — gender-aware seed profile photos (~80% mix, initials fallback). Also injects a **platform-wide hover-name tooltip**: any element with `data-mstip="…"` shows a fixed-position bubble on hover (escapes overflow clipping). Now loaded on Gallery too.
- `image-slot.js` — drag/drop image element w/ crop, SVG support, persists per id.

**Key pages:** Home (dashboards per role) · Store · Projects + Project-Autumn Giveaways · Basket · Orders · Organisations · Team · Chats · Brand Assets · Distributor/Customer Settings · Status Reference · plus concept pages (Site Map, Org & User Model, Price Matrix Concept, Supplier Onboarding, Brand Guide).

## 2. The product modal (core of the app)

Opened from any project/gallery row. Left rail = sections (Design / Price / Sample / Stock), each shows ONE section at a time. Shared module: **`product-modal.js`** + `product-modal.css`.

- **Design** = two stages, **Visual** then **Proof**, each with its own status + version (Visual vN / Proof vN). Proof can start before visual approval, but **Order needs BOTH approved**. Statuses: Not started → With studio → Information needed ("Give feedback") → Awaiting approval → Changes requested → Approved (+ Unbranded). Requesting proof changes auto-reverts the visual to "reworking". Proof viewer: full-screen, per-position artwork + proof visuals, branding method/colour swatches w/ PMS, magnifier.
- **Product Builder** (distributor, inside Design): §1 project colours/variants required → §2 single product colour for the design → §3 positions → §4 visuals → §5 proof (per-position uploads, notes, warnings, sizes) → §6 Sample options → §7 Other (unbranded toggle).
- **Price** — live slider + price-break matrix; customer sees sell prices + savings + discount; distributor sees cost→markup→sell, profit. **Modal Price tab at full parity with `Price Matrix Concept.html`** (Jun 2026). **Distributor view = "Calculations" (editable) above which sits "Results" (read-only).** Calculations holds **collapsed accordions** (open-state persists across refresh via `d.price._accOpen`): (1) **Price matrix** (Design-chosen branding highlighted — method chip + tinted colour-count rows; **cost view shows the unbranded item + each branding method as an additional per-unit charge with setup amortised in — `methodDecoCostAt`; sell view shows the full branded sell price — `methodSellAt`**), (2) **Override prices** (locked-price editor: column window, live sell/profit recompute, revert, two-supplier split, Request-quote-check → pick contacts → simulate reply → quote feeds cells), (3) **Additional charges** (two-sided supplier→dist cost AND dist→cust sell, inline tables), (4) **Distributor discounts** (resolution chain + per-line override). Results: quantity (continuous 5-unit slider + editable single-unit box; ticks under thumb), customer sell price (**pre-discount struck → post-discount**), your margin — a **worked-example calc panel** (`marginCalcHTML`, like the concept page: Unbranded × qty → Decoration × qty → Setup → Total supplier cost → ×Markup band → Total sell price (list) → −Discount → Net sell → Distributor profit → Unit sell price → Profit/unit), delivery (country switcher), **5 · Discount** (applied % + source + £ saving), **6 · Additional charges** (read-only mirror of both sides — customer/sell + supplier/cost — auto-updates as they're edited in Calculations). **The unit sell price holds across a break tier and only steps at the next break** (`priceView`/`repQty` — unit & markup computed at the tier's break threshold; the leading `{q:0}` "from" tier anchors to the first real break so sub-first-break quantities hold too; cost & delivery are actual-quantity; rail `priceSummary` uses the same). **Discounts** (concept §5) resolve most-specific-active-wins: per-product → per-project → per-customer → category → site-wide, in `localStorage['ms-discounts']` (`MSModal.resolveDiscount/discountsConfig/saveDiscountsConfig`; `d.price.discountPct` = per-line override, >0 active). Site-wide/category/per-customer set on **Customer Settings → Discounts tab** (distributor-only); per-project on the project. Full matrix also carries two-supplier sections + per-country delivery + profit rows. **Expiry**: approved shows date + "Expire now"; editable "valid N days" per product/project. The **"Submit for approval" status bar is pinned to the bottom**. Slider uses real (q>0) breaks only (leading `{q:0}` "from" tier stays in the matrix). All logic in `product-modal.js`; both host pages get it for free.
- **Sample** — options shown depend on Builder (unbranded always on; branded if selected; "not required" skips the order gate). Each has product image (unbranded=store image, branded=proof), cost modes (cost price / supplier quote / free) → ×1.35 markup. Unbranded sample has colour/variant chooser w/ stock flags + add-to-basket. Cost pulls from Store product "Sample cost" (`ms-sample-costs`).
- **Stock** — colour×size matrix; API-fed (auto in-stock) / manual check / made-to-order; in-project colours tagged, design-chosen highlighted; supplier reservation flow.

**Width (Sep 2026):** the coloured band is full-bleed and `.msf-in` has **one width on every page** — no cap, no centring, sharing the page's gutter (`clamp(20px,2.5vw,36px)`, matching `.main`). ## 5. Conventions / gotchas
- **Page width (Sep 2026)** — **every page is full-bleed and left-aligned**: `width:100%;max-width:none` plus fluid `clamp()` padding, so content starts on the same left edge as the footer and uses the whole window. Applies to the whole app including Admin panels, the customer-facing content pages and the Status Reference. Earlier schemes (a three-tier cap, then a 1080/1600 exception for prose pages) were dropped in favour of one consistent format. Only the standalone reference and concept documents — which have no app shell — keep their own caps. Watch the prose pages on very wide monitors: paragraphs there are held by their own `max-width` on the text element, not by the page column.
- **One gutter token: `--page-gutter`** (`tokens.css`, `clamp(20px,2.5vw,36px)`). The content column (`.main`/`.wrap`), the breadcrumb/store band (`.crumbband`/`.storeband`) and the footer (`.msf-in`) all take their horizontal padding from it, so every page has a **single left edge** top to bottom. Before this, the gutter was hand-written per page — three different clamps plus a fixed `36px` on the bands, which left three edges on some pages. **Use the token on any new page**; never hard-code the horizontal padding on those elements.
- **Always give a column-flex child an explicit `width`, not just a `max-width`.** A flex item only stretches on the cross axis when its cross size is `auto` *and* neither cross-axis margin is `auto` — so `.main{max-width:860px;margin:0 auto}` sized itself to its content, which is why Distributor Settings jumped width between tabs. The fix is to add `width:100%`; **keep `margin:0 auto`**, which is still what centres the column once the viewport exceeds the cap. The rail layout (`.ms-content`) is column flex on every page, so this applies platform-wide.
- **Finance nav (`sidebar.js`)** — the old top-level **Invoices** link is a **Finance** rail section (its flyout holds Invoices, plus Credit Limit for customers) for all three roles (distributor / customer / supplier — new for suppliers), housing **Invoices**; the **customer** also gets a **Credit Limit** sub-item. Targets are `#finance=invoices` / `#finance=credit` placeholders (pages not built yet).
- **View switcher (`identity.js`)** now also loads on **Merchsmith Admin.html** (with `logos.js`+`avatars.js` deps), so you can switch perspective from Platform Admin. Each identity row in the switcher menu has a **home shortcut** (`.msid-home` house icon) that switches to that identity AND navigates to its `land` page (Admin→Admin.html, others→Home.html). The row body still switches in place where pages are shared.
- **Data portability (`ms-data.js` → `window.MSDATA`):** the prototype keeps everything in `localStorage` (per-browser, no backend). `MSDATA.snapshot()` auto-discovers **all `ms-*` keys** (31+ incl. store layout, curated range, dist range, ingested products, briefs, baskets, orders, themes…). **Admin → Settings → Data backup**: "Download" (.json backup) / "Restore" (overwrite from file — recovers a clear-site-data wipe) / "Copy embed" (a `<script>window.__MS_SNAPSHOT__=…</script>` snippet to paste into a shared/exported HTML's `<head>`). On load, `ms-data.js` auto-calls `MSDATA.applyEmbedded()` which seeds from `__MS_SNAPSHOT__` **only if the browser has no ms-* data** (never clobbers a real user) — so a shared export opens with the author's configured data. `ms-data.js` is loaded early (before catalogue-data) on Admin, Store, Distributor Settings. **Caveat:** still per-browser; true shared/permanent persistence needs the backend (going-live phase). "Clear site data" can't be blocked by any web page — backup/restore is the seatbelt.
- **Modal left rail (facts panel)** lives in the HOST pages (`renderRail`), split by hairline dividers into **Price · Delivery date · Collaborators**. Price rows are engine-driven via `MSModal.priceSummary(p)` and **two-way synced with the Price tab quantity** (rail qty box ↔ price-tab slider/box, through `ctx.onQty` + host `updateRailPrice`). Distributor sees Quantity · Sell/unit · **Sell total** · Cost total · **Profit**; customer sees Quantity · Est./unit · Line/Est total. Collaborators shows `COLLABORATORS[]` avatars (`MSAvatar.html`, laid out **horizontally**) with `data-mstip` hover names. Keep `Merchsmith Project - Autumn Giveaways.html` (grouped rail) and `Merchsmith Gallery.html` (flat rail) in sync.
- **Discounts config** (`ms-discounts`) is read by the modal AND edited on Customer Settings → Discounts; both share the same default shape `{sitewide,category:{},customer:{},project:{}}`.
- **Two near-identical product views:** `Merchsmith Project - Autumn Giveaways.html` (table) and `Merchsmith Gallery.html` — keep their inline JS blocks in sync. Both share `product-modal.js`, `order-data.js`, etc.
- **Persistence keys (localStorage):** `ms-dash-state` (product statuses), `ms-basket4` / `ms-orders`, `ms-sample-costs`, `ms-brand-assets`, `ms-address-book`, `ms-basket-addr-notes`, `ms-email-drafts`, `ms-theme` / `ms-custom-themes` / `ms-crumb-colours`, `ms-brand-logo` / `ms-cust-logo` (+tones), `ms-identity` / `ms-role`. Branding keys also mirror to the project sidecar `ms-branding.state.json` so they survive a fresh browser.
- **Branding is permanently persistent** for testing — colourways, breadcrumb colours, and logos restore from the sidecar even after close/reopen.
- **Developer Index history cards** (`Merchsmith Developer Index.html`): every page card carries a dated change-history (`h:[[ISO date, change], …]`, newest first — first entry drives the “last modified” stamp and the newest-first sort). **Update it with every batch of changes** (standing instruction, Jul 2026). Dates before Jul 2026 are retrospective estimates.
- **One icon per concept, across all four roles** (Sep 2026). The rail is built twice — `sidebar.js` (`I.*`) for distributor / customer / supplier, and an inline `a-*` sprite in `Merchsmith Admin.html` — so a concept can drift between them. The agreed mapping: Dashboard = bar chart (labelled **Dashboard** everywhere, never "Overview"), Store = shop awning, Projects = merch cube, Products = tag, Organisations / Distributors = building, Suppliers = delivery truck, Team = two people, Chats = speech bubble, Finance = document, Settings = gear, Recommended range = star, Store layout = layout, Subscriptions = card. Check BOTH sets when adding a nav item; the trap is a glyph that is unique within one role but already means something else in another (the admin Suppliers cube was the shell's Projects cube).
- Icons = inline `<svg><symbol>` sprite per page. **Bake the presentation attrs onto the `<symbol>` itself** — `fill="none" stroke="currentColor" stroke-width="1.7" stroke-linecap="round" stroke-linejoin="round"` — never rely on a CSS class alone. Rasterisers that don't resolve `<use>` inheritance ignore the CSS and fill the shapes, so rect-based icons (grid, card, layout) come out as **solid black blocks** in screenshots, PDFs and the Developer Index thumbnails. Swept across the platform Sep 2026: 94 symbols baked over 12 pages. Deliberately solid marks (`ic-bangdot`, `i-mark`, `o-noproof`, `o-branded`) declare their own `fill` on the child shapes and are left alone — check a symbol's children before baking.
- html-to-image screenshots overlap multi-line text (font-timing artifact) — verify layout via `eval_js` bounding boxes, not screenshots.
- Customer is **Citrix** throughout (renamed from "Canal & River Trust"); initials **CX**.
