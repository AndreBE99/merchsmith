Distributor branding builder

How the distributor specifies the decoration for a product — product colour, then each branding position with its method and number of print colours. These choices drive the proof spec and the decoration price.

Mock-up only — nothing live has changed. Built so you can react to the flow before we wire it into the modal's Design area.

2How a method behaves

  • Screenprint / Pad print — per-colour: the print-colour stepper sets 1–N colours (each adds a screen / setup).
  • DTF / Full-colour transfer — full colour: no stepper, shown as “Full colour”.
  • Embroidery — priced per 1,000 stitches; colours up to the machine head count.
  • Laser engrave — single tone; shown as “Single tone”.
  • No decoration — marks the line unbranded (no proof needed).

2.5Product colour & variant selection

  • Step 1 now captures the product colour and a variant (e.g. size) where the product has them. Both are stored on the chosen build (productColour + variant).
  • Stock link: the selected colour + variant are highlighted in the modal's Stock section — a banner names the choice, the chosen colour card is outlined and the chosen variant row is flagged, shown against the live availability grid. This lets the distributor sanity-check stock for exactly what the design uses.
  • Basket link: at the order stage only the selected colour (+ variant) appears as a single line — not every colour row — so the order reflects the actual specified product.
  • If no colour is chosen, the basket falls back to listing the available colours for the buyer to set quantities against.

3Where it lives & what it feeds

Distributor builds branding→ Proof spec (positions, method, colours)→ Decoration price→ Customer approves proof
  • Sits in the modal's Design area for the Distributor role (the customer sees the result, read-only, in the proof).
  • Each position's method + colour count flows straight into the proof spec and the Price tab's decoration component.
  • The chosen product colour + variant flow into the Stock section (availability highlight) and the Basket (only the selected option is ordered).
  • Changing the build after a proof is released bumps the proof to a new version for re-approval.
