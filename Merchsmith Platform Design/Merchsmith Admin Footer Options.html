Why this one

  • It surfaces the backup warning platform-wide. Right now that only appears if you go looking in Settings → Data backup. On a prototype with no backend, that is the single highest-consequence thing an operator can forget.
  • Feed health earns its place. Stale supplier data is the most common cause of wrong prices in the store, and nothing on the platform currently shows it at a glance.
  • Reference docs stop being invisible. Field mapping, status reference and the feed spec exist but are only reachable from the Developer Index.

Trade-off

  • Keeps every screen's working area intact, which matters on the product database and curated range.
  • Loses the feed-by-feed status, the restore action, and the grouped navigation — the backup warning survives as a single line.

Open questions before I build it

  • Which option — or A on the Overview and B everywhere else, which gets the full picture on the landing screen without taxing the working pages.
  • Is the status line real or decorative? I can wire it to genuine counts (products, suppliers, distributors) and real feed timestamps, or leave it indicative for now.
  • Editable? The distributor footer is configurable because distributors brand themselves. Admin is Merchsmith's own console, so I would hard-code it unless you want the links managed.
